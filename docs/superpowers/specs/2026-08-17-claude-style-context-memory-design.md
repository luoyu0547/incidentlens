# IncidentLens Claude Code 式上下文与记忆设计

## 目标

将当前“每轮重建一份截断状态快照”的实现改为连续的 Agent 消息循环，并采用 Claude Code 的核心原则管理上下文：完整历史可恢复、活跃上下文有界、便宜的压缩先执行、昂贵的语义压缩最后执行。

本阶段只处理单次调查及其子任务的上下文连续性，不实现跨事故 Project Memory。

## 核心原则

1. Agent 的核心仍是一个循环：模型请求工具时执行工具并继续；没有工具请求时结束或暂停。
2. 完整消息历史只追加、不覆盖；压缩只改变下一轮送给模型的活跃上下文。
3. 工具输出先持久化，再缩短模型看到的内容，避免先丢信息后压缩。
4. Session Memory 保存当前工作的连续性，不替代 Evidence，也不能绕过证据归属校验。
5. Todo、当前目标和用户约束属于工作状态，压缩后必须恢复。
6. 子 Agent 使用独立消息历史，只向父 Agent 返回结构化结果和证据引用。
7. 所有自动压缩和错误恢复都有次数上限，禁止无限重试。

## 总体结构

### 完整历史

为每个 `AgentRun` 保存 append-only transcript。每条记录包含：

- user 消息；
- assistant 文本与工具请求；
- 与工具请求对应的 tool result；
- Todo 更新；
- compact boundary；
- 终止、暂停和恢复事件。

transcript 保存模型实际看到的消息、工具结果预览及其持久化引用，不因后续压缩而改写。完整工具输出继续由 EvidenceStore 保存。现有 Investigation、ToolCall、Evidence、Checkpoint 等结构化状态仍是执行与审计的事实来源。

### 活跃上下文

每次模型调用前，从最近 compact boundary 开始重建活跃消息，并附加：

- 当前调查或子任务目标；
- scope、剩余预算和审批状态；
- 当前 Todo；
- 最新 Session Memory；
- compact boundary 之后的消息；
- 当前允许使用的工具定义。

不再每轮重复发送全部假设、证据和子报告。旧内容通过 Memory、Todo 和按需读取工具恢复。

### 消息组

一个 assistant 工具请求与紧随其后的 tool result 是不可拆分的消息组。裁剪、重试和恢复都以消息组为单位，不能留下孤立的工具请求或工具结果。

循环是否继续以 assistant 内容中是否存在工具请求为准，而不是仅依赖流式响应结束原因。

## 压缩管线

每次模型调用前严格按以下顺序运行。

### 1. 工具结果预算

先把完整工具结果写入现有 EvidenceStore，再把模型可见的结果写入 transcript。若同一轮工具结果总量超过预算，transcript 和活跃上下文都只保存：

- 有界预览；
- 执行状态；
- evidence ID 或持久化结果 ID；
- 重新读取完整内容的方法。

工具结果预算默认使用 200,000 字符，并允许配置。该步骤必须先于其他压缩，以免完整内容先被占位符替换。

### 2. 中段裁剪

当消息组数量超过上限时，保留初始任务和最近消息组，裁掉中间历史，并插入一条边界说明。裁剪不修改 transcript。

以下内容不能被单独裁掉：

- 工具请求与对应结果；
- 待审批操作及审批结果；
- 当前 Todo 引用的最近执行结果；
- 当前正在等待的子任务及其完成通知。

### 3. 旧工具结果占位

将较旧的大型工具结果替换为简短占位符，保留工具名、状态、引用 ID 和重新读取方式。最近三个工具结果默认保留完整内容。

失败结果、状态未知结果和待审批结果必须保留到相应状态被处理完成。

### 4. Session Memory 快速压缩

当活跃上下文接近预算时，先从现有结构化状态生成 Session Memory，不调用模型。Memory 必须包含：

- 当前目标；
- 用户明确约束；
- 当前 Todo 及状态；
- 已确认事实与证据 ID；
- 活跃假设；
- 未决问题；
- 已完成的重要动作；
- 子任务结论；
- 下一步建议；
- 覆盖到的 transcript sequence。

新 revision 只追加。Memory 覆盖边界之前的历史不再作为“最近增量”重复注入。

### 5. 语义压缩

前四步仍不能满足预算时，使用独立压缩调用生成结构化摘要。压缩调用不能使用任何工具，只能返回符合 schema 的内容。

摘要必须保留目标、约束、Todo 状态、事实及证据 ID、关键动作、未知项、文件或资源引用、子任务状态和下一步。压缩结果不能创建新事实。

连续三次压缩失败后熔断。本次调查继续使用确定性 Session Memory 和更小的最近窗口，不再自动反复调用压缩模型。

### 6. Prompt 过长后的应急压缩

模型接口明确返回 prompt-too-long 时：

1. 保存当前完整 transcript；
2. 保留最近约五个完整消息组；
3. 对更早内容执行语义压缩；
4. 本轮重新调用模型一次。

同一轮第二次失败时安全暂停调查，记录失败原因和恢复所需信息，不再重试。

## 上下文预算

预算对象必须覆盖实际发送内容：

- system prompt；
- 工具定义；
- 活跃 messages；
- Todo、Session Memory 和任务附件；
- 为模型输出预留的 token；
- 安全缓冲。

触发线为：

`上下文窗口 - 最大输出 token - 安全缓冲`

模型适配层能提供 token 计数时使用真实计数；不能提供时使用保守估算，并用每轮返回的实际输入 token 校准估算比例。字符数只能作为降级手段，不能继续宣称为精确 token 预算。

## Todo

新增持久化 Todo 状态，而不是只把“下一步”埋在摘要文本里。每项包含：

- 唯一 ID；
- 内容；
- `pending`、`in_progress` 或 `completed` 状态；
- 可选的 evidence ID 和 tool call ID；
- 更新时间。

同一时间最多一个 Todo 为 `in_progress`。复杂任务首次执行动作前应先建立 Todo；每完成一个阶段就更新状态。Todo 不增加执行权限，只用于防止长调查偏离目标。

Todo 在 compact 后直接恢复，不依赖语义摘要是否记住。

## 工具执行

工具定义与执行处理器通过统一注册表管理。新增工具只增加工具定义和处理器，不修改 Agent 循环。

一次响应包含多个工具请求时，保持原始顺序划分连续批次：

- 明确标记为并发安全的连续工具可并发；
- 写操作、审批操作和状态不确定操作串行；
- 批次之间严格按顺序执行。

每个请求仍经过现有 schema 校验、scope 校验、权限和审批检查。上下文压缩不能跳过这些检查。

## 子 Agent

父 Agent 只向子 Agent 传递：

- 明确的任务描述；
- 收窄后的 scope；
- 独立预算；
- 明确授权的 evidence ID；
- 完成标准。

子 Agent 使用独立 transcript、Todo、Session Memory 和压缩状态，不继承父 Agent 的完整 messages。父级取消信号向子级传播。

子 Agent 完成后只返回结构化 ChildReport、证据引用和必要的文件系统副作用说明；中间推理和工具输出不复制到父上下文。禁止无限递归委派，沿用现有深度与数量限制。

## 恢复

进程重启后按以下顺序恢复：

1. 读取 AgentRun、Checkpoint、审批和在途工具状态；
2. 读取最新 compact boundary 与 Session Memory；
3. 从 transcript 恢复 boundary 之后的完整消息组；
4. 恢复 Todo；
5. 对在途工具执行现有安全恢复策略；
6. 在下一轮调用前重新运行上下文预算和压缩管线。

恢复不回放已经完成的有副作用工具。状态无法确定时继续使用现有 `PAUSED_UNCERTAIN_STATE`，等待人工处理。

## 错误处理

- transcript 写入失败：不调用模型，不执行下一批工具，安全暂停；
- 工具结果持久化失败：不把结果标记为成功；
- Session Memory 写入冲突：重新读取最新 revision 后重建上下文；
- 语义摘要 schema 无效：丢弃该摘要并计入熔断器；
- prompt-too-long：每轮仅一次应急压缩；
- compact 后证据引用不属于当前 run：拒绝摘要 revision；
- compact 后工具请求与结果无法配对：拒绝该活跃上下文并从上一个边界恢复。

## 数据边界

新增或替换的核心对象：

- `TranscriptEntry`：append-only 原始消息或边界事件；
- `MessageBlock`：text、tool use、tool result、Todo reminder 等内容块；
- `CompactBoundary`：压缩覆盖范围、摘要 revision 和恢复元数据；
- `SessionMemory`：增加 transcript sequence、约束、Todo 摘要和下一步；
- `TodoItem`：持久化工作计划项；
- `ContextBudget`：窗口、输出预留、安全缓冲和当前估算；
- `CompactionState`：连续失败数、本轮是否响应式压缩及最近成功边界。

现有 `AgentTurnRequest` 的全量状态快照职责被活跃消息上下文替代。Investigation、AgentRun、Evidence 和 ToolCall 仍保持原有领域职责。

## 测试与验收

### Agent 循环

- 有工具请求时继续循环，无工具请求时结束；
- 流式结束原因不准确时仍能根据内容执行工具；
- 多工具批次保持顺序和并发安全边界。

### 压缩

- 工具结果先持久化再占位；
- tool use/result 永不被拆开；
- 最近结果、待审批和失败结果按规则保留；
- 压缩不修改完整 transcript；
- Memory 边界之前的内容不作为最近增量重复发送；
- 实际发送内容不超过配置预算。

### 记忆与 Todo

- 压缩后目标、约束、Todo、事实、证据 ID、未知项和下一步仍存在；
- 重启后恢复相同 Memory revision、Todo 和消息尾部；
- Memory 不能让不属于当前 run 的证据通过校验。

### 子 Agent

- 子 Agent 不接收父 transcript；
- 子 Agent 只能访问任务包授权的范围和证据；
- 父 Agent 只接收最终报告；
- 父取消可终止子任务。

### 失败恢复

- 连续三次语义压缩失败后熔断；
- prompt-too-long 最多重试一次；
- 第二次过长后安全暂停；
- 重启不会重复执行已完成的写操作。

## 不在本阶段实现

- 跨事故 Project Memory；
- 用户偏好自动提取与 Dream 整理；
- 向量检索或 embedding；
- 跨项目共享记忆；
- 为压缩保存或暴露隐藏推理。
