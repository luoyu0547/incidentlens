# IncidentLens 远程诊断控制面设计

日期：2026-08-10
状态：已通过对话评审，等待书面规格复核

## 1. 背景与目标

IncidentLens 是运行在开发人员本地电脑上的单用户诊断工具。它通过用户已有的 SSH 配置连接多台运行 Docker Compose 的服务器，帮助用户观察日志、调查跨服务故障、检查配置与源码，并在严格的安全约束下进行诊断性修改。

它不是服务器端守护进程，也不是发布系统。远端服务器只需配置用户的 SSH 公钥和必要的 Docker/文件权限，不安装 IncidentLens Agent。本文中的 Agent 指本地运行的模型调查循环。

产品需要解决四个核心问题：

1. 将多服务器、多服务日志统一可视化，优先过滤错误和警告；没有错误或警告时仍展示能反映服务状态、调用关系和异常沉默的关键正常日志。
2. 提供类似 Claude Code 的模型工具循环，但由独立 Harness 控制预算、上下文、证据和权限。
3. 让模型像操作本地文件一样，在持久 SSH 会话中使用远程 Read、Edit、Write、Search 和 Shell，避免依赖 `vi`、复杂 `sed`、一次性 Python 修改脚本或本地落盘后手动传输。
4. 防止模型在生产服务器上执行不可控操作：普通远程编辑必须双重备份，服务中断操作必须审批，`rm -rf` 永久禁止。

## 2. 范围

### 2.1 MVP 范围

- 单用户、本地运行。
- Docker Compose 服务器，通过 SSH 连接。
- CLI 为主要交互入口。
- 本地 Web UI 用于日志、调查过程、父子会话、diff、备份和审批的可视化。
- 按需和持续两种日志采集模式。
- 持久宿主机 SSH 会话，以及拥有独立模型上下文的容器子会话。
- 远程文件读取、搜索、多处编辑、写入、校验、恢复和 Shell。
- 本地与远端双重备份。
- 本地源码路径注册、动态源码发现和诊断性修改。
- 带证据引用、实际 diff 和验证结果的调查报告。

### 2.2 非目标

- 不负责 Git commit、push、PR、CI、正式镜像构建或生产发布。
- 不要求在服务器部署 IncidentLens 进程。
- 不在 MVP 支持 Kubernetes。
- 不将整份项目源码复制到 IncidentLens 数据库。
- 不承诺仅凭日志或编译产物一定能定位代码级根因。

## 3. 总体架构

采用“本地常驻 Runtime + CLI/Web 双客户端”方案。

CLI 和 Web UI 都连接同一个本地 Runtime，而不是分别运行 Agent。Runtime 持有模型循环、SSH 会话、容器子会话、日志采集、审批状态、证据、备份和调查检查点。CLI 退出或浏览器刷新不会自动终止后台会话。

主要组件如下：

- `SessionManager`：维护持久 SSH、PTY、SFTP、keepalive 和重连。
- `AgentRuntime`：运行父 Agent、创建容器子 Agent、控制预算和上下文。
- `RemoteToolGateway`：实现远程 Read/Edit/Write/Search/Shell，不向模型暴露凭据。
- `PolicyEngine`：执行操作风险分类、审批规则和永久禁止规则。
- `ChangeManager`：管理双重备份、多文件 ChangeSet、原子写入、验证和回滚。
- `LogManager`：执行按需查询、持续采集、解析、脱敏、索引和关联。
- `EvidenceStore`：保存日志片段、文件快照、命令输出、diff 和证据引用。
- `ProjectRegistry`：保存目标、服务、本地源码路径和允许的日志路径。
- `ApprovalManager`：将审批绑定到完整参数和内容哈希，并向 CLI/Web UI 广播。
- `LocalAPI`：为 CLI 和 Web UI 提供统一的本地 API 和事件流。

本地结构化数据使用 SQLite；日志正文、文件快照和备份保存在权限受限的本地数据目录。SSH 私钥继续由用户的 SSH 配置或系统密钥代理管理，不复制到 IncidentLens 数据库。

## 4. 持久远程会话

### 4.1 宿主机会话

`HostSession` 表示一台服务器上的持久 SSH 连接。它保存：

- 目标服务器和登录用户。
- 持久 SSH 连接及 keepalive 状态。
- PTY 与 SFTP 通道。
- 当前工作目录和允许的环境状态。
- 已读取文件的版本哈希。
- 本次调查的工具、备份和审批记录。

一次工具调用结束不会断开会话。模型通过 `session_id` 调用：

- `remote_read`
- `remote_list`
- `remote_search`
- `remote_stat`
- `remote_diff`
- `remote_edit`
- `remote_write`
- `remote_restore`
- `remote_shell`

`remote_edit` 接受精确文本替换或结构化 patch。Runtime 在内存中应用编辑，通过现有 SSH/SFTP 连接写入同目录临时文件并原子替换。模型不需要操作 `vi`，也不需要生成一次性 Python 脚本或大量 `sed` 命令。

`remote_shell` 使用持久 PTY，使 `cd`、环境激活和长时间命令的状态可以跨工具调用延续。Shell 仍经过策略检查，不能成为绕过安全工具的后门。

### 4.2 容器子会话

进入容器时不改变父 HostSession 的上下文。Runtime 创建独立的 `ContainerSession` 和子 Agent：

```text
spawn_container_agent(host_session, container, task, evidence)
```

每个容器子会话拥有：

- 独立的模型上下文和工具调用历史。
- 独立的工作目录、PTY、环境和证据空间。
- 仅限目标容器和授权路径的远程工具。
- 独立的轮次、工具、时间和输出预算。
- 从父 Agent 接收的精简任务包。

子 Agent 完成后仅向父 Agent 返回结构化报告和证据引用。大量源码、日志和命令输出保留在子会话的证据库中，不直接填入父上下文。子会话可暂停、恢复、取消或并行存在；关闭子会话不会断开父 SSH 会话。

## 5. 工具事件与审批状态

所有工具调用形成可审计事件：

```text
requested -> policy_checked -> running -> output_stored -> completed
```

需要审批时：

```text
requested -> awaiting_approval -> approved | rejected -> running
```

每个事件至少记录调查、父/子会话、目标、工具名称、脱敏参数、操作理由、策略决策、输出摘要、完整输出引用、时间和状态。

模型调用工具前提供一段简短、可展示的操作理由。CLI 和 Web UI 展示理由、参数、状态和结果摘要，但产品不展示或依赖模型的隐藏思维过程。

## 6. Agent 调查循环与 Harness

调查不是固定的配置/源码检查清单。Agent 根据证据动态选择下一步：

```text
理解症状
-> 提出可验证假设
-> 选择下一项低风险操作
-> 执行工具
-> 保存原始结果并提取证据
-> 更新假设和置信度
-> 继续、派生子 Agent 或形成结论
```

Harness 在模型外部强制：

- 最大调查轮次、工具调用数、运行时间和输出量。
- 结论必须引用本次调查中存在的证据 ID。
- 报告区分已确认事实、推断和未知项。
- 缺少可访问源码时可以推测，但必须降低置信度并说明缺失信息。
- 修改后必须验证；未验证的修改不能声明问题已解决。
- 连续多轮没有新证据时停止循环并汇报。
- 子 Agent 不能自行扩大服务器、容器、路径或权限范围。
- 遇到审批、连接异常、证据冲突或不确定写入状态时暂停。

### 6.1 上下文分层

- 活跃上下文：症状、服务拓扑、当前假设、关键证据和剩余预算。
- 调查记忆：已排除假设、配置差异、服务关系、子 Agent 报告和操作历史。
- 原始证据库：完整日志、文件快照、命令输出和 diff，不直接进入模型上下文。

上下文接近限制时，Runtime 创建结构化检查点，保留：已确认事实、未确认假设、已排除原因、证据 ID、远程会话状态、修改与备份、待审批操作和建议下一步。

子 Agent 返回至少包含：状态、根因、置信度、证据 ID、修改、验证结果、剩余问题和建议动作。

## 7. 日志采集与查询

日志采用混合模式：

- 按需查询：通过 SSH 获取指定服务器、服务和时间范围的 Docker 日志或白名单文件日志。
- 持续监控：用户显式开启后，本地 Runtime 增量采集并保存游标；停止监控后不再占用远端连接。

支持 Docker stdout/stderr，以及项目注册表明确允许的宿主机或容器日志文件。Agent 不能自行扩大文件日志路径范围。

标准日志字段包括：

- 时间、目标、Compose 项目、服务、容器。
- 来源类型和来源路径。
- 日志级别、正文、trace/request ID。
- 模式指纹和采集模式。

级别按结构化字段、项目规则、stderr/常见格式的顺序识别。无法确定时标记为 `unknown`，不武断归类为错误。

没有 error/warning 时，系统显示关键正常日志和异常信号：服务生命周期、健康检查、请求和跨服务调用、外部依赖连接、重试、耗时、最后活动时间、日志突然中断和服务异常沉默。

Agent 先使用 `log_overview`、`log_search`、`log_tail`、`log_context`、`log_correlate` 和 `log_pattern_summary` 缩小范围。只有选定片段进入模型上下文，完整日志留在本地证据库。

MVP 使用 SQLite FTS5 建立本地索引，日志正文可分块压缩。进入模型上下文前进行敏感字段脱敏；原始数据仅保存在本机受限目录。

## 8. 项目注册表与源码发现

项目注册表仅保存路径和关联信息，不保存源码内容：

```text
Project
|- project_id
|- display_name
|- local_source_paths[]
|- targets[]
`- services[]
   |- compose_service
   |- container_names
   |- local_source_path
   |- container_path_hints[]
   `- allowed_log_paths[]
```

`container_path_hints` 只是发现提示，不能当作容器一定含源码的事实。

容器子 Agent 在每次调查中动态检查镜像 ID/digest/labels、Compose 配置、挂载点、工作目录、启动命令、目录结构和文件类型，并判断：

- 容器是否包含可读且足够完整的源码。
- 容器是否主要包含字节码、JAR、bundle 或二进制产物。
- 本地和远端内容能否通过 commit、构建标签或哈希建立版本关系。

Agent 根据当前问题和证据决定检查配置、远端源码、本地源码或编译产物，而不是依赖固定的 dev/release 流程。

行为边界：

- 本地和远端源码均可访问：可对比，并根据调查需要修改和验证。
- 仅本地源码可访问：可以分析和编辑本地源码，但必须说明远端验证限制。
- 仅远端源码可访问：可以在容器中调查、临时修改和验证，最终导出 diff 和说明。
- 当前没有可访问源码：继续分析日志、配置和运行状态，结论标记为推测，并说明需要的项目路径或源码版本。

IncidentLens 可以修改已注册的本地源码，但不负责后续 Git 和发布工作。远端容器内修改属于诊断性修改，报告必须说明其临时性和容器重建后的丢失风险。

## 9. ChangeSet、双重备份与回滚

所有远程文件修改进入 `ChangeSet`：

```text
draft
-> preflight
-> locally_backed_up
-> remotely_backed_up
-> applied
-> validated
-> verified | failed | rolled_back
```

预检记录原内容哈希、权限、所有者、大小、修改时间和符号链接状态。文件在读取后发生变化时拒绝覆盖，要求重新读取和生成 patch。

每个远程文件在写入前必须形成两份备份：

- 本地：IncidentLens 数据目录下按目标、调查和 ChangeSet 分层保存。
- 远端：原文件同目录，名称为 `<原文件名>.incidentlens-backup.<UTC时间戳>`。

流程要求：

1. 下载原文件到本地备份库并校验 SHA-256。
2. 在远端原目录使用保留元数据的复制方式创建时间戳备份并校验 SHA-256。
3. 两份备份均成功后，才允许写入。
4. 新内容写入同目录临时文件，恢复权限和所有者。
5. 执行适用的语法、配置或静态检查。
6. 使用原子替换提交修改。
7. 保存完整 diff、备份路径、验证输出和恢复记录。

多文件 ChangeSet 必须先完成所有文件的双重备份，再开始应用。中途失败时恢复已修改文件，不能留下未声明的半完成状态。

本地备份可能包含密钥或 `.env` 等敏感数据，因此数据目录仅当前用户可访问；敏感备份采用本地加密，模型上下文和普通日志不得输出未脱敏内容。

## 10. 安全与审批策略

风险分级：

- 自动允许：读取、搜索、白名单日志查询、普通本地编辑、已完成双重备份的普通远程文件编辑。
- 强制审批：停止/重启/删除/重建容器，Compose stop/restart/down/up，切换镜像，网络和端口修改，系统包安装，以及会改变服务可用性的命令。
- 永久禁止：任何同时具有递归和强制语义的 `rm` 调用，不因目标路径或用户审批而放行；同时阻止明显等价的破坏性批量删除。
- 无法分类或超出策略：暂停并请求用户决定，模型不能自行降低风险级别。

审批绑定完整命令、目标、参数、镜像、ChangeSet 和内容哈希。审批后任何相关内容改变都会使批准失效。批准只适用于该次具体操作。

服务重启或重建完成后必须执行预先展示的验证计划。验证失败时不得宣称解决，并提供回滚。若回滚会中断服务，同样需要用户确认。

Shell 命令需要结构化风险检查，不能仅靠简单字符串匹配。Runtime 还必须限制模型可见的工具和凭据，阻止模型自行建立绕过 PolicyEngine 的 SSH 连接。部署时建议使用满足工作需要的最小权限 SSH 账号，形成运行环境层的第二道边界。

## 11. 调查报告

调查结束时生成本地可审计报告，至少包含：

- 症状、影响范围和时间线。
- 已确认根因或带置信度的推测。
- 触发条件和服务关系。
- 日志、配置、文件和命令证据引用。
- 已排除原因。
- 本地及远端实际修改 diff。
- 修改前后的验证结果。
- 两地备份和可恢复状态。
- 正式修复建议。
- 尚未验证的风险和需要开发人员完成的工作。

报告明确区分诊断性远端修改和正式仓库修改。IncidentLens 到报告与验证为止，不接管 Git 和发布流程。

## 12. 故障恢复

- SSH 短暂断开：自动重连 HostSession 并恢复工作目录；写入状态不确定时重新核对哈希后暂停。
- PTY 或容器退出：保留子 Agent 上下文和证据，允许重新创建容器会话。
- Runtime 重启：从检查点恢复调查、审批和 ChangeSet；不自动重放结果未知的危险操作。
- 日志流断开：从游标继续；断点无法确定时记录日志缺口。
- 子 Agent 崩溃或超预算：向父 Agent 返回部分证据和未完成状态。
- 本地存储损坏或空间不足：停止持续采集和远程写入；安全范围内的只读诊断可继续。
- 文件冲突：拒绝覆盖，保存远端当前版本和 Agent 基于版本以供重新比较。

## 13. 测试策略

### 13.1 单元测试

- 策略矩阵和审批失效。
- 命令风险识别与 `rm -rf` 阻止。
- patch、多处编辑和版本冲突。
- 双重备份、哈希和元数据校验。
- 上下文检查点、证据引用和结论约束。
- 日志级别、脱敏和关联规则。

### 13.2 协议测试

- 模拟 SSH/SFTP/PTY 的连接复用和状态保持。
- 断线重连及不确定写入处理。
- 宿主机与容器子会话隔离。
- 多个子 Agent 的并发、取消和恢复。

### 13.3 集成测试

使用本地 Docker Compose 沙箱验证：

- 多服务按需日志和持续日志。
- 大文件多处远程编辑，不使用一次性脚本。
- 多文件 ChangeSet 和两地备份。
- 服务操作审批、重启验证和回滚。
- 父 Agent 派生容器子 Agent 并接收结构化报告。

### 13.4 安全测试

- `rm -rf`、命令混淆和明显等价删除。
- 路径穿越、符号链接替换和竞态修改。
- 审批后参数或哈希变化。
- 本地/远端备份失败和写入中断。
- SSH 凭据、敏感日志和备份内容泄露。
- 子 Agent 尝试扩大目标或权限。

## 14. MVP 验收标准

MVP 完成时，用户能够：

1. 在本机注册至少一台 Docker Compose 服务器和本地源码路径。
2. 在 CLI 中发起调查，并在 Web UI 中实时查看同一调查。
3. 按服务查询与持续采集 Docker/白名单文件日志。
4. 查看错误、警告以及没有错误时的关键正常日志。
5. 由父 Agent 创建拥有独立上下文的容器子 Agent。
6. 在持久 SSH 会话中像本地工具一样读取、搜索和多处编辑大型远程文件。
7. 在任何远程覆盖写入前得到通过哈希验证的本地与远端备份。
8. 阻止 `rm -rf`，并在停止、重启、删除或重建服务前获得逐次审批。
9. 在修改后执行验证，并在失败时提供可审计的回滚路径。
10. 获得包含根因、证据、diff、验证结果和开发建议的最终报告。

## 15. 后续阶段

MVP 验证后再考虑 Kubernetes 适配器、团队身份与权限、外部日志后端、Git/CI 集成和正式发布自动化。这些能力不得改变当前设计中的工具策略、证据、审批和备份边界。
