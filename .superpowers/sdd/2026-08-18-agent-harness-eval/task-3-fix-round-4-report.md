# Task 3 fix round 4 report

## RED evidence

After removing the production-wide `__latest__` rewrite, the existing workflow unit test failed consistently with `RuntimeError: fake recording workflow did not complete: failed`. The completed stop still cited the literal placeholder, so real evidence validation rejected it. This reproduced the stated `paused_missing_evidence`/failure root cause rather than weakening the completion assertion.

## Root cause

`FakeProvider.generate_turn` globally scanned every request message and rewrote any `StopStep` conclusion containing `__latest__`. That made generic fake-provider behavior depend on conversation contents and silently changed literal evidence IDs. Removing it exposed the test fixture's reliance on a magic ID: the fixture needed a run-specific evidence reference generated by `log_query`, but only supplied the placeholder.

## Fix

- Removed the global magic-ID rewrite from `apps/control-plane/src/incidentlens_control_plane/investigation/fake_provider.py`.
- Added the narrow public `FakeProviderRegistry.pop_step(run_id, request)` dispatch hook. The default implementation is request-independent and simply pops the next step; generic provider semantics remain literal and unchanged.
- Added `_RecordingRegistry` only in `tests/integration/test_live_model_workflow_unit.py`. It overrides `pop_step`, observes the request after `log_query`, collects actual `ToolResultBlock.evidence_ids`, and binds those IDs into the pending test-only completion step.
- Kept the workflow's strict completed assertion and added checks that the conclusion contains no magic ID and cites only returned owned evidence.
- Added a FakeProvider regression proving a literal `"__latest__"` evidence ID is preserved unchanged.
